# Deep Search for Research — v0

## Project goal

Deep Search for Research is a local web application that turns any web page or
uploaded document (image or PDF) into a concise, structured summary. It crawls a
URL, runs OCR on uploaded files, sends the extracted text to a locally hosted
large language model (via Ollama), and produces a summary plus a short title,
core keywords, and related web-search results. Everything runs locally:
summaries, titles, and keywords are generated by an on-device LLM, and the
companion web search is routed through a self-hosted SearXNG instance. Results
are persisted in a PostgreSQL database and fetched by a React + TypeScript
frontend.

## Core capabilities

- **Summarize a URL** — crawl any public web page (with host validation) via
  `crawl4ai` and summarize the harvested markdown.
- **Summarize an uploaded file** — supports images and PDFs; PDFs are rasterized
  page-by-page and OCR'd with a local OCR model.
- **Local LLM summarization** — text is summarized, titled, and keyworded by an
  on-device model (Ollama, default `qwen2.5:3b`), with streaming response and
  progress events sent to the UI over Server-Sent Events (SSE).
- **Companion keyword search** — after keywords are extracted, the app queries
  SearXNG and surfaces the top results alongside the summary.
- **Result persistence** — every summary, its title, keywords, and search results
  are stored in PostgreSQL (table `summaries`) so they can be listed and
  retrieved later.
- **Streaming UI pipeline** — the frontend consumes SSE events
  (`status`, `summary_chunk`, `keywords`, `title`, `search_results`,
  `search_error`) and renders progressively as each stage completes.

## Architecture

- `backend/` — FastAPI app (Python) that owns:
  - request validation (URL scheme/host allow-listing),
  - URL crawling,
  - OCR for images/PDFs,
  - the summarization pipeline (summary streaming, title + keywords in parallel,
    SearXNG search),
  - PostgreSQL storage and REST endpoints.
- `frontend/` — React + TypeScript + Vite + shadcn/ui app that provides the
  user interface and drives the backend via SSE and REST calls.
- `searxng/` — a SearXNG instance used as the anonymizing web-search back end.
- Shared config: `pyrightconfig.json`, runtime settings via environment
  variables (local model name, OCR model, SearXNG URL, DB URL, timeouts, etc.).

## Key runtime dependencies

Ollama (local model server), `httpx` (SearXNG client), `asyncpg` (Postgres),
`crawl4ai` (web crawling), `pdf2image` + OCR (document/images), PostgreSQL,
and a React/Vite frontend.

## Summary of the pipeline

1. User submits a URL or uploads an image/PDF.
2. Backend validates and extracts text (crawl or OCR).
3. Local model streams a summary; title + keywords are generated in parallel.
4. As soon as keywords are ready, SearXNG is queried with them.
5. Everything (title, summary, keywords, search results) is saved to Postgres.
6. Frontend streams the events and displays the final summary.

## Notes / assumptions

- The app assumes a local Ollama instance and a self-hosted SearXNG instance are
  running; the database URL defaults to a local PostgreSQL database.
- Summaries are generated with a fixed prompt that forbids the words
  "summary"/"Summary" in its own output and formats results with bullet points
  and paragraphs.
- Output is optimized for a research/reading workflow: a short title, a
  readable summary, a set of keywords, and cited web sources.
